# 第 3 批改造说明 · 本地 Stable Diffusion（CPU 模式）

> 落地计划书 3.3.2「本地图像生成」，与既有通义万相云端 API 组成**双轨**。
> 定案：**不启用显卡**（用户实测 RTX 5060 Laptop 跑不动，明确固定 CPU）。

---

## 一、决策记录

| 议题 | 结论 | 依据 |
|---|---|---|
| 用不用 GPU | **不用，固定 CPU** | 用户实测 Blackwell sm_120 跑不动；torch 保持 `2.11.0+cpu` |
| 模型选型 | **SD1.5 + LCM-LoRA** | 相比 SD-Turbo 质量明显更好；LCM-LoRA 把 20~25 步压到 6 步，速度接近 Turbo |
| 调用策略 | **默认关闭，手动切换** | `IMAGE_BACKEND=tongyi`；前端新增「本地 SD（CPU，较慢）」选项，用户显式选择才走本地 |
| LoRA 是否自训 | **否** | LCM-LoRA 是公开的加速器权重（128MB），下载即用，不需要喂数据训练 |

## 二、依赖修复（必须先解决，否则一切免谈）

**问题**：venv 内 `transformers 4.53.2` 直接 `ImportError`：

```
huggingface-hub>=0.30.0,<1.0 is required ..., but found huggingface-hub==1.4.1
```

transformers 不可用 → diffusers 拿不到 CLIP tokenizer / text encoder → **pipeline 根本构造不出来**。
（这也解释了第 2 批为什么要在 `memory.py` 里自己实现 token 估算。）

**根因**：`huggingface-hub 1.4.1` 是被 `paddlex`（与本项目无关的包）拉上来的。

**修复**：降到 `0.36.2`，同时满足三方约束：

```
diffusers   -> huggingface-hub<2.0,>=0.34.0
transformers-> huggingface-hub<1.0,>=0.30.0
tokenizers  -> huggingface-hub>=0.16.4,<1.0
```

**附带修复**：`peft` 缺失导致 `load_lora_weights()` 抛 `PEFT backend is required`，
LCM-LoRA 静默失效 → 退化成「标准调度器 + 6 步」→ 画质崩坏。
已装 `peft 0.21.2` + `accelerate 1.15.0`，并纳入 `available()` 检查与契约测试。

**关键坑（FIX-7）**：`StableDiffusionPipeline.from_single_file()` 在只给单个 `.safetensors` 时，
会去远端拉 `stable-diffusion-v1-5` 的 `model_index.json` —— 离线/网络受限时直接报
`no file named model_index.json found`。必须用 `config=` 显式指向本地配置目录。

核心设计（针对 16GB 内存 + 无 GPU）：

```python
# 1. 懒加载：进程启动不加载模型，首次出图才载入（约 2.7s）
# 2. bf16：Zen4 原生 AVX512-BF16，权重内存减半

# 6. SD_UNLOAD_AFTER=true：出图后 del + gc.collect()，不常驻内存
# 7. torch.inference_mode()：关闭梯度记录，进一步降峰值
```

## 五、实测数据（真实权重，CPU）

环境：AMD Ryzen 9 8945HX（16C32T）/ 15.8GB 内存 / torch 2.11.0+cpu / bf16。

| 指标 | 数值 |
|---|---|
| 模型加载 | **2.7s** |
| 纯推理（512×512，6 步，LCM） | **16.9s** |
| 总耗时（含加载） | **20.1s** |
| 进程 RSS 峰值 | **4.3 GB** |
| 系统可用内存最低点 | **1.67 GB**（出图前 5.46GB） |
| 出图后（已卸载） | 内存回落至 3.52GB |
| 输出质量 | 512×512 动漫立绘，构图完整、面部干净，无明显崩坏 |

真实出图样例：`back/app/static/images/4/1792324702.png`（银发少女 / 海边小镇 / 日落）。

### 内存安全阈值

实测出图会吃掉约 **3.8 GB** 可用内存。若加载前只剩 3.8GB，出图途中可用内存会压到接近 0，
系统直接杀进程（**实测发生过：一次加载把后端进程打崩，日志无任何输出**）。

因此 `SD_MIN_FREE_RAM_GB` 从 3.0 提到 **4.5**：

- ≥ 4.5GB → 正常出图，过程中至少还剩 ~0.7GB
- < 4.5GB → 1.5 秒内快速拒绝，返回明确原因，**不再崩溃**

## 六、实测发现并修复的问题（写入 Bug 清单）

| 编号 | 问题 | 影响 |
|---|---|---|
| **FIX-5** | 前端传 `model`，服务层读 `model_id`，参数名对不上 | 本地 SD 永远选不中，静默走云端 |
| **FIX-6** | 前端文本下拉写死 `model='deepseek'`，原样传给 Ollama 会 404 | 与 FIX-1 同类，本地 Ollama 再次被静默绕过 |
| **FIX-7** | `from_single_file` 默认联网拉 SD1.5 配置 | 离线环境加载直接失败 |
| **FIX-8** | Celery broker 挂掉时 `task.delay()` 重试约 64 秒才失败 | 请求长时间挂起（实测 64s 才回退同步） |
| **FIX-9** | `debug=True` 的 watchdog 监视到 `site-packages`，torch 文件一动就热重载 | 后端静默消失、日志无异常（`WinError 10038`） |

**FIX-9 补充**：这个问题伪装得极像「内存不足被杀」，实际是 reloader 机制 bug。
关闭 `use_reloader` 后不再复现。日志必须写到项目目录之外，否则每写一行都会触发一次重载。

FIX-8 修复：`_submit_task` 先用 1 秒 TCP 探测 broker，连不上直接走同步。

## 八、已知限制

### ⚠️ 最常见的问题：内存不够（不是 bug）

本机 **日常可用内存只有 2~4GB**（15.8GB 总量，但 Edge/QQ/DeepSeek 客户端等长期占用 10GB+），
而出图需要 **4.5GB**。所以「出图失败」九成是这个原因。

- 后端会返回明确原因，并**直接列出该关哪几个程序**：
  ```
  可用内存不足，拒绝加载本地 SD（需要 ≥4.5GB，当前 3.8GB）。
  建议先关闭：QQ（1.0GB）、Edge 浏览器（0.9GB）、DeepSeek 客户端（0.5GB）。
  ```
- 前端在选择「本地 SD」后点击生成时，会**先查内存再决定是否发起**，不会白等一次失败。
- 随时可用体检工具查看：
  ```bash
  cd back && ./.venv/Scripts/python.exe ../docs/_src/check_memory.py
  ```
  它会告诉你差多少、谁在吃内存、关掉哪些能达标。

> `SD_MIN_FREE_RAM_GB` 保持 **4.5** 是刻意选择：实测出图吃约 3.8GB，
> 低于此值会压到 1GB 以下，机器明显卡顿甚至卡死。宁可拒绝，也不把电脑拖垮。

### 其它限制

1. **速度**：CPU 512×512 约 **17 秒/张**（含加载 20s）。这是硬件上限，不是代码问题。
   想更快只能降步数（4 步起）或降分辨率（384×384）。
2. **Celery 异步路径未实测**：验证时 Docker Desktop 未运行，Redis 容器起不来，
   走的是同步回退。异步投递的代码路径已具备（`SD_TIMEOUT=900` 足够），
   但**需要在 Redis 起来后补一轮验证**。
3. **分辨率**：默认 `SD_MAX_PIXELS=262144`（512×512）。
   768×768 会被自动缩到 512×512。CPU 上再大不仅是慢，是可能直接 OOM。
4. **中英文提示词**：Counterfeit 是英文训练的，写英文 prompt 效果明显更好。
5. **不要开 reloader**：`manage.py` 已默认关闭（`use_reloader=False`），
   需要热重载时显式设 `FLASK_USE_RELOADER=1`。原因见 FIX-9。

## 九、如何启用

```bash
# 1. 后端 .env
IMAGE_BACKEND=local          # 全局默认走本地（也可保持 tongyi，前端下拉临时切）
SD_MIN_FREE_RAM_GB=4.5

# 2. 确认权重就位
ls back/.models/
#   Counterfeit-V2.5_fp16.safetensors   lcm-lora-sdv1-5.safetensors   sd15-config/

# 3. 健康检查
curl http://127.0.0.1:8088/ai/health | jq .local_sd
#   { "ok": true, "model_exists": true, "lora_exists": true, ... }

# 4. 前端「AI 创作」页，图像模型选「本地 SD（CPU，较慢）」
```

**降级行为**：本地 SD 不可用（权重缺失 / 内存不足 / peft 缺失）时，
返回明确错误信息，不会崩溃，也不会静默切到云端。
