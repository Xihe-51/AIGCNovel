## 二、实测发现并修复的问题

### 🔴 A-1 后端完全不校验 JWT，可任意伪造身份（最严重）

**现象（修复前实测）**

```text
GET /project/projects           # 不带任何 token
Header: X-User-Id: 4            → 200，返回该用户全部项目
GET /user/profile               # 不带任何 token
Header: X-User-Id: 4            → 200，返回邮箱等个人信息
GET /project/projects
Header: X-User-Id: 1            → 200，直接读到 1 号用户的项目
```

**根因**

- 登录接口确实签发了 JWT（`user/views.py`），但**全项目没有任何一处校验它**；
- 所有视图只读 `request.headers['X-User-Id']`，而这个头完全由客户端控制；
- `flask_jwt_extended` 虽然初始化了，却从未使用。

**修复**

新增 `back/app/security.py`：

- `init_auth(app)` 注册全局 `before_request`：除白名单外，一律要求
  `Authorization: Bearer <token>`，并用 `SECRET_KEY` 验签、校验过期；
- token 里的 `identity` 必须与 `X-User-Id` 一致，否则 **403**；
- `current_user_id()` 统一取当前用户，视图不再直接信任请求头；
- 白名单：登录/注册/找回密码/健康检查/公开项目列表/公开市场查询/静态资源；
- 前端 `utils/request.ts` 增加 401 拦截：清 token 并回登录页。

**验证**

```text
未登录访问项目列表          → 401
仅伪造 X-User-Id            → 401
token=4 但 X-User-Id=1      → 403
token=4 + X-User-Id=4       → 200
```

### 🔴 A-2 项目资源缺少归属校验（横向越权）

**现象**：登录后拿到自己的 token，把 URL 里的 `scene_id` / `content_id` / `character_id`
换成别人的，即可读写他人数据。RAG 的三个接口（status / rebuild / search）也只按
`project_id` 取数，不校验归属。

**修复**

- `project` 蓝图新增 `before_request` 统一归属校验：
  从路径参数（`project_id` / `scene_id` / `content_id` / `character_id` / `avatar_id` / `path_id`）
  或请求体（`project_id` / `character_id` / `avatar_id`）推导项目，校验 `project.user_id == 当前用户`；
- 写操作一律 404 拒绝；**GET 且项目 `is_public=true` 时放行**（支持他人预览公开作品）；
- `ai` 蓝图：`/ai/rag/status|rebuild|search` 与 `/ai/continue_story` 增加项目归属校验；
- 批量立绘接口校验所有角色都属于当前用户。

**验证**

```text
他人读取本项目            → 404
他人修改本项目场景        → 404
他人读取本项目剧情图      → 404
公开项目他人预览场景/角色 → 200
```

### 🟠 A-3 `/ai/health` 冷启动阻塞 30s+（前端 AI 页像卡死）

**现象**：后端刚启动时第一次请求 `/ai/health` 会挂起 30 秒以上；前端 `AiView` 一进入就调它。

**根因**：`_local_sd_health()` / `_local_music_health()` 在**请求线程里**首次
`import torch / diffusers / transformers`，冷启动导入极慢。

**修复**：新增 `back/app/ai/health_warmup.py`：

- 应用启动时用后台 daemon 线程预热重型模块并缓存探测快照，每 30 秒刷新（可用内存是动态的）；
- `/ai/health` 只读快照，未就绪时返回 `warming: true` 与轻量占位，**永不阻塞请求**；
- 前端本来就对 `local_sd` 缺失做了兜底，因此预热期间不会误拦截。

**验证**：修复后 `/ai/health` 首次 **0.022s**、后续 **0.003s**（此前 30s+）。

### 🟠 A-4 找回密码是纯 UI 摆设

**现象**：`LoginView` 的「发送验证码」只是 `forgotStep++`，点两下直接显示"密码重置成功"；
后端无任何 forgot/reset 路由。

**修复**

- 后端新增 `POST /user/forgot_password` 与 `POST /user/reset_password`：
  - 6 位验证码，10 分钟有效，最多尝试 5 次；
  - Redis 可用时写 Redis，不可用时进程内存储（单进程部署足够）；
  - **不暴露邮箱是否已注册**，避免用户枚举；
  - 未配置邮件服务时，开发模式（`DEBUG=true`）回传 `debug_code` 便于自测，生产环境不返回；
- 前端 `LoginView` 改为真实调用，校验邮箱/验证码/密码长度，展示后端错误信息；
- `api/login.ts` 新增 `forgotPassword` / `resetPassword`。

**验证**：发送 → 重置 → 新密码登录成功 → 改回原密码成功；错误验证码返回 400。

### 🟠 A-5 公开项目只能看列表，点进去 404

**现象**：首页切到「公开项目」，点击卡片跳 `/view/:id`，`ExportProject` 拉场景/角色时
被归属校验拦截（此前虽然没校验，但 `get_project_by_id` 也按 owner 过滤，实际同样打不开）。

**修复**：归属校验对 `GET + is_public` 放行（见 A-2），公开作品可被他人只读预览，写操作仍拒绝。

### 🔴 A-6 有分支的项目无法删除（外键 1451）

**现象（实测）**

```text
DELETE /project/project/14
→ 400
{"message": "删除项目失败: (pymysql.err.IntegrityError) (1451,
 'Cannot delete or update a parent row: a foreign key constraint fails
  (`aigc`.`branch_paths`, CONSTRAINT `branch_paths_ibfk_3` ...)')"}
```

**根因**：`delete_project()` 先删 `script_contents`，但 `branch_paths.source_content_id /
target_content_id` 仍外键引用这些行；而删除分支的代码排在其后，且异常被 `try/except` 吞掉只打印。

**修复**：把「删除分支路径」提到最前面，按 `project_id` 或「起点/终点属于该项目」清理，
再删对话/场景/角色；去掉吞异常逻辑，失败时正常回滚并返回错误。

**验证**：新增回归「有分支的项目可正常删除」，36 项审计全过；清理了此前失败遗留的测试项目。

## 四、仍然存在的限制（未在本轮处理）

1. **Redis / Celery 异步链路未复测**：本机 Docker 未启动，走的是同步回退；
   代码路径与第 3 批一致，Redis 起来后建议再跑一次 `test_batch12_e2e.py`（届时跳过项会变成实测）。
2. **资源市场付费是模拟支付**：二维码 + 倒计时 + 直接放行，没有真实支付网关，也没有订单表。
3. **设计文档中的部分重功能未实现**：角色关系图谱可视化编辑、场景多图层/镜头控制/动态天气、
   分支节点拖拽式编辑器（目前是只读拓扑 + 选择项编辑）。
4. **存档仍只写 localStorage**（P3-4），换设备/清缓存会丢。
5. **`SECRET_KEY` 默认值仍是 `ailab`**：务必在 `back/.env` 设置随机值，否则知道默认值即可伪造 token。
6. **验证码在开发模式回传前端**：这是为了无邮件服务时能自测；上线前应配置邮件通道并关闭该行为。
7. **`npm run build` 的 vue-tsc 类型检查仍未修**（历史遗留 75 个错误），日常请用 `npx vite build`。
