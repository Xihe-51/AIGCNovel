# 第 10 批：节点级剧情图（P1-5）

> 对应【P1 产品深度】第 5 项。
> 此前「剧情树」是**按场景聚合**的只读视图（`ProjectView.vue` 里把 content-level 的边
> 折叠到场景对场景）；本批升级为 **content-level 节点 + 拖拽连线 + 条件编辑**。

---

## 1. 目标与边界

| 要做的 | 不做的 |
|---|---|
| 每个 `script_contents` 渲染成一个节点 | 不新增后端表 / 不改动后端接口 |
| 拖拽节点调位置（位置记忆） | 不做协作实时同步 |
| 从节点拖线到另一个节点 = 新建分支 | 不做撤销/重做栈 |
| 点连线编辑「选项文案 + 显示条件」 | 不做 Ren'Py 导出（后置项） |
| 整树覆盖保存写回 `branch_paths` | 不做自动保存（显式「保存拓扑」） |

---

## 2. 设计决策

| 项 | 决策 | 理由 |
|---|---|---|
| 后端 | **零改动** | `GET /project/story_graph/<pid>` 已经返回 content-level `nodes` + `edges` + FSM 校验；`POST /project/branches/<pid>/batch` 已支持整树覆盖 |
| 节点位置 | `localStorage['aigcn.storyGraph.<pid>']` | 纯作者侧视觉元数据，不值得为它加表/迁移；换浏览器只是位置回到自动布局 |
| 保存方式 | `batchSaveBranches(pid, edges, replace=true)` | 一次请求完成「新增 + 修改 + 删除」，与后端「整树覆盖」语义一致 |
| 顺序边 | 前端镜像后端 `auto_sequence` | 后端只为「无显式出边」的节点合成顺序边；前端同样算一遍，虚线展示自然播放流，不写库 |
| 边的语义 | 非「选择」节点的出边会明示提示 | 播放器 `currentChoices` 只在 `content_type==='选择'` 时读 `branch_paths`；非选择节点的显式边只影响 FSM 结构校验，UI 必须讲清楚，避免误以为能跳转 |

---

## 3. 前端实现

新增组件 `front/src/components/StoryGraphEditor.vue`，由 `ProjectView.vue` 的剧情树工具栏
「🧩 节点级编辑」打开（独立 `el-dialog`，`destroy-on-close` 保证每次重新拉取）。

### 3.1 画布

- 画布坐标：节点左上角 `_x/_y`，节点尺寸固定 `210 × 70`。
- 自动布局：按 `scene_order` 分列、列内按 `order_num` 排序，列宽 300 / 行高 94。
- 视图变换：`translate(pan) scale(scale)`，`transformOrigin: 0 0`；滚轮缩放（0.3~2）、
  空白处拖拽平移。屏幕坐标 → 画布坐标用 `toCanvas()` 反变换。
- 连线路由：起点取源节点右中 `(x+210, y+35)`，终点取目标节点左中 `(x, y+35)`。
  实线（粉）= 显式分支，虚线（灰）= 顺序播放；边中点标选项文案，带条件时追加 `◇`。

### 3.2 交互

| 操作 | 行为 |
|---|---|
| 拖节点主体 | 移动节点；`mouseup` 时写 `localStorage` |
| 拖节点右侧圆点 | `startConnect` 起一条临时虚线；`mouseup` 命中目标节点 → `edges.push` 新边并标脏 |
| 点击节点 | 面板显示类型/场景/内容/出边列表（点某条出边可跳去编辑） |
| 点击连线 | 进入连线面板：起点、终点、选项文案、显示条件（变量/运算符/值）、删除 |
| 保存拓扑 | 调 `batchSaveBranches(..., replace=true)` → 重新拉取（path_id 会刷新） |

- 前端拦截：`source==target` 自环、已存在的重复边，直接提示不提交。
- 条件写入：`conditions = variable ? {variable, op, value} : null`，与后端 `_normalize_conditions` 对齐。
- `edgeForm` 通过 `watch(deep)` 回写边对象；`selectEdge` 时用 `formSyncing` 标志避免误标脏。

## 6. 端口占位：排查结论

| 端口 | 占用进程 | 说明 |
|---|---|---|
| 8088 | `D:\conda\envs\aigc\python.exe -m flask run` | 后端（`/ai/health` 200）。**同时存在 `back\.venv\…\manage.py` 的重复进程**，但只有 conda 那个真正 LISTEN 8088（历史遗留的「双进程单监听」） |
| 5175 | `front\node_modules\…\vite --port 5175` | 本项目前端 |
| 5173 | `D:\history-master\front` vite | **另一个项目**，勿混用 |
| 8080 | `java -jar target\back-0.0.1-SNAPSHOT.jar` | 另一个 Spring 项目 |
| 8000 / 6380 | wslrelay / docker | Docker 代理与 Redis |

结论：本项目端口未被外部抢占，唯一需要收拾的是**两个后端进程并存**——
建议只保留 `back\.venv\…\python.exe -X utf8 manage.py`，杀掉 conda-env 那个，
避免日后重启时两个 Flask 争抢 8088、DB 连接落到非预期进程。
