# 第 5 批 · 分支节点与样式修复

> 本轮针对两个具体问题：**「设置分支节点」到底能不能用**、**页面样式（CSS）的明显 bug**。
> 结论：分支功能此前**只能算半成品**（库里有数据但编辑器不显示、不能跨场景、删不掉），
> 现在已打通并做了真实 UI 点击验证；样式方面找到并修掉 3 类会直接影响观感的问题。

---

## 一、分支节点：实测结论与修复

### 1.1 之前为什么"看起来不能用"

用无头 Chrome 真实点击验证，发现 4 个叠加问题：

| 编号 | 问题 | 表现 |
|---|---|---|
| B-1 | `ensureChoices()` 在 `projectId` 赋值**之前**执行 | 打开「选择」节点，已有分支选项**一个都不显示**（库里有，界面空） |
| B-2 | 保存对话后整个对象被替换 | 已加载的 `_choices` 丢失，选项从界面消失，必须切类型/重进才回来 |
| B-3 | 跳转目标只取**当前场景**的对话 | 无法把分支连到其它场景的节点，分支叙事被限制在单场景内 |
| B-4 | 删除带分支的对话 / 非空场景 | 外键 1451，接口 500（`branch_paths` 引用 `script_contents`，`script_contents` 又引用 `scenes`） |
| B-5 | **播放器完全不读分支** | `ExportProject` 只按 order_num 线性播放，配好的分支在预览/发布里根本不生效 |

### 1.2 修复

- **B-1**：`fetchSceneData()` 先 `projectId.value = sceneData.project_id`，再拉对话，
  最后 `await Promise.all(...ensureChoices)`；预加载顺序正确。
- **B-2**：保存后写回 `{ ...saved, _choices: dialogue._choices }`，保留已加载选项；
  新保存的节点同时并入 `projectNodes`，可立即被其它节点选为目标。
- **B-3**：新增 `loadProjectNodes()` 调 `/project/story_graph/<pid>` 拿**全项目节点**；
  目标下拉改为「项目内全部已保存节点 ∪ 当前场景节点」，并显示 `场景名 · #序号 角色：内容`。
  删除对话时同步从 `projectNodes` 移除。
- **B-4**：删除顺序统一为 **分支边 → 对话 → 场景**：
  - `delete_dialogue()` 先删 `source_content_id` 或 `target_content_id` 等于该节点的边；
  - `delete_scene_by_id()` 先删该场景对话相关的边，再删对话，最后删场景；
  - `delete_project()` 之前已修（第 4 批）。
- **B-5**：播放器接入分支：
  - 加载项目时一并拉 `/project/branches/<pid>`；
  - `currentChoices` 按 `source_content_id === 当前节点` 取选项，渲染成按钮；
  - `selectBranch()` 找到 `target_content_id` 所在场景与下标并跳转；
  - 「选择」节点**阻止**点击/自动播放继续前进，必须等玩家选择；
  - 跳转时记录历史对话、切换背景音乐。
- **剧情树刷新**：`ProjectView` 监听 `activeTab`，从「场景编辑」切回「概览」时自动重拉拓扑，
  不再需要手动点「刷新数据」。

## 二、样式（CSS）问题

### 2.1 场景编辑器横向溢出 98px

**现象**：进入「项目 → 场景编辑」后，`.el-tabs__content` 的 `scrollWidth=1440`，
而 `clientWidth=1342`，多出 **98px**，出现横向滚动/右侧被裁切。

**根因**：`SceneEdit.vue` 的根容器写了 `width: 100vw`。组件嵌在项目页 tab 内
（父容器 1342px），`100vw` 永远等于 1440px，必然溢出。

**修复**：`width: 100%`。修复后 tab 内容不再溢出。

### 2.2 分支目标下拉文字被截断

**现象**：`.choice-target-select` 固定 `160px`，而目标文案是
「场景一 · #1 旁白：这是起点」，实际可用宽度只有 116px，文字被切掉。

**修复**：改为 `flex: 1 1 240px; min-width: 180px;`，并对 Element Plus 的
placeholder/selected-item 加 `text-overflow: ellipsis`。目标文案现在能完整显示（过长省略）。

### 2.3 背景图 / 音乐 / 立绘加载失败（反斜杠路径）

**现象**：项目 7 的场景背景、音乐、立绘 URL 在库里是
`\static\project\7\image\xxx.png`（Windows 反斜杠）。前端 `BASE_URL + url` 拼出来的地址
在 CSS `url()` / `<img>` 里不可靠，表现为**背景空白、音乐不播、立绘不显示**。

**根因**：`save_uploaded_file()` 用 `os.path.join()` 得到 `app\static\...`，再
`.replace('app','',1)`，反斜杠原样落库（与 FIX-11 同类，但这次影响场景/立绘）。

**修复**：
1. 上传返回值统一 `replace('\\','/')` 并补前导 `/`，新数据不再产生反斜杠；
2. 一次性迁移库内 9 个字段（3 个场景背景 + 3 个音乐 + 3 张立绘）；
3. 实测三个资源 URL 均返回 200，大小正确。

> 若以后还有历史数据，执行 `docs/_src/fix_paths.py` 即可（幂等）。

### 2.4 「上传素材」弹窗超出视口，底部按钮点不到

**现象**：市场页「上传素材」对话框实际高 **1100px**，而窗口只有 1000px：
对话框底部到 1250px，`footer` 在 1167–1233px，**确定按钮完全在视口外**。

**根因**：`el-dialog.orange-dialog` 没有高度约束，表单内容把对话框撑高；
Element Plus 默认 `margin-top:15vh` 又把它整体下推。

**修复**：给 `.orange-dialog` 加全局样式（dialog 会 teleport 到 body，scoped `:deep` 选不中）：
`max-height:90vh; display:flex; flex-direction:column; margin-top:5vh;`
并让 `.el-dialog__body` `overflow-y:auto; max-height:calc(90vh - 150px)`。

**验证**：对话框高度 1100 → **895px**，footer 底部 928px（< 1000），按钮可见，正文可滚动。

## 四、仍未做的分支能力

1. **剧情树只读**：节点不能拖拽改位置/连线，连线只能在「选择」节点的下拉里配。
2. **没有条件编辑 UI**：`branch_conditions`（如「好感度 > 50」）接口支持，但前端没有编辑入口。
3. **剧情图按场景聚合**：画布节点是「场景」，不是每条 `script_contents`；
   想看节点级拓扑需要再做一个 content-level 视图。
4. **FSM 校验对回环敏感**：分支指回起点会报 CYCLE/ORPHAN，这是校验器的设计（死循环检测），
   不代表分支没保存成功。
