## 一、总体结论

原文档描述的是一个「设计蓝图」，实际代码已经演进为一个可运行的系统，并且**新增了大量文档中没有的功能**。
同时存在**文档有、代码没有**的字段与功能（详见第三章）。

技术栈也发生了**实质性替换**：

| 模块 | 文档描述 | 代码实际 |
| --- | --- | --- |
| 文本生成 | ollama + deepseek | ✅ **DeepSeek 官方云端 API**（`api.deepseek.com`，模型 `deepseek-chat`） |
| 图像生成 | stable diffusion + Counterfeit-V2.5 | 🆕 **通义万相 wanx-v1 异步 API**（`dashscope.aliyuncs.com`） |
| 音乐/语音 | stable diffusion + musicgen-small | 🆕 **火山引擎 TTS 语音合成**（`openspeech.bytedance.com`） |
| 前端框架 | Vue3 + TS + Pinia | ✅ Vue3 + TS（**未发现 Pinia 实际使用**，组件内直接用 ref） |
| 后端 | Flask + MySQL + Redis | ⚠️ Flask + MySQL（**未发现 Redis 实际使用**） |

> 注：后端目录中并无 `stable diffusion` / `musicgen` / `ollama` 的调用代码，全部已改为调用第三方云 API。

## 二、新增功能清单（文档未记录）

### 2.1 项目概览 —— 可视化剧情树（🆕 核心新增）

原文档「项目概览面板 - 故事树可视化导航」只是一句需求描述，代码中实现了一个**可交互的画布式剧情树编辑器**。

- 位置：`front/src/views/ProjectView.vue`（项目概览 → 「高级功能预览」按钮 → 弹窗）
- 能力：
  - 从 `scenes` 表实时生成节点，**自动布局**（每行 3 个，行高 140 / 列宽 260）
  - **SVG 箭头连线**（`marker-end` 箭头标识）
  - 节点**类型自动推断**（基于标题/描述关键词）：
    - 第 1 个场景 → `start` 起始节点 🎬
    - 标题含「结局/最终/尾声/结尾/结束/终」→ `ending` 结局节点 🏁
    - 标题含「分支/选择/分岔/岔路」→ `branch` 分支节点 🔀
    - 其他 → `middle` 中间节点 📖
  - **画布交互**：滚轮缩放（0.3~2.0）、空白处拖拽平移、节点拖拽移动、点击选中
  - **工具栏**：放大 / 缩小 / 重置 / 刷新数据
  - **节点属性面板**：显示场景ID、序号、描述、类型
- ⚠️ 局限：
  - 节点数据源**只有 `scenes` 表**，**不读取 `branch_paths` 表**，所以图中的「分支」只是靠标题关键词"猜"出来的，**并非真实分支拓扑**
  - 节点拖拽位置**不会持久化**（刷新即回到自动布局）
  - 节点位置用 `clientX/clientY` 计算但未除以 `scale`，缩放后拖拽会有偏移

### 2.2 对话 FSM 状态机（🆕）

- 位置：`front/src/components/SceneEdit.vue`
- 定义了一套四态机：`draft` 草稿 → `ai_generated` AI生成 → `reviewed` 已审核 → `published` 已发布
- 有 `fsmStates`、`fsmStateLabels`、`dialogueFsmStates`、`getFsmState()`、`setFsmState()` 及完整 CSS 样式
- ⚠️ **但模板中没有任何地方使用它** —— 属于**写了但没接上的死代码**（见第三章）

### 2.3 场景拖拽排序（🆕）

- 位置：`front/src/components/ScenesManage.vue`
- 原生 HTML5 `draggable` 实现场景列表拖拽排序
- 拖拽后本地立即更新（乐观更新）+ `Promise.all` 批量调 `PUT /project/scenes/{id}` 持久化
- 有 300ms 延迟显示拖拽提示，避免误触发

### 2.4 对话排序（🆕）

- 位置：`SceneEdit.vue` + 后端 `POST /project/dialogues/reorder/<scene_id>`
- 上移 / 下移按钮 + 「确认以当前顺序重新排序」按钮
- 后端 `reorder_dialogues()` 会校验 ID 归属，重排 `order_num`

### 2.5 AI 辅助对话生成（🆕 垂直整合亮点）

- 位置：`SceneEdit.vue` 每条对话的「AI 生成」按钮
- **上下文感知**的 Prompt 组装：
  - 当前场景标题、对话类型、角色名、当前内容
  - **近邻策略**：当前索引 ≤ 10 时，取前 5 条原文作为「最近对话历史」
  - **远期策略**：当前索引 > 10 时，用 `generateHistorySummary()` 生成「先前剧情摘要」（出场角色、对话/旁白条数、关键台词拼接，限制 200 字）+ 最近 3 条原文
- AI 返回结果可「应用到当前对话」

### 2.6 语音上传（🆕）

- `SceneEdit.vue` 每条对话支持上传语音（`file_type: 'voice'`），存 `script_contents.voice_url`
- 播放器预览时自动播放角色语音

### 2.7 视觉小说播放器（🆕 播放端）

- 位置：`front/src/views/ExportProject.vue`，路由 `/view/:projectId`
- 能力：
  - 背景图 + 角色立绘 + 对话框三层分层渲染
  - **背景音乐**自动播放（含浏览器自动播放限制的 `once` 监听绕过）
  - **自动播放模式**：按文本长度动态延时（基础 3 秒，每 100 字 +1 秒）
  - **历史对话弹窗**（`H` 键或滚轮上滚触发），按场景过滤
  - **功能按钮区**：查看历史 / 隐藏对话框 / 快进 / 自动播放 / 重新开始 / 存档 / 退出
  - **本地存档**：`localStorage` 保存 `currentSceneIndex`、`currentDialogueIndex`、历史对话
  - 键盘操作：空格/回车推进，`H` 查看历史
  - 空文本 `content_text === ""` 时自动切换对话框显隐（`judge()` 函数，用于做"清屏"效果）

### 2.8 公开项目 / 社区浏览（🆕）

- 位置：`ScenesManage.vue` 「公开项目」按钮 → `PUT /project/project/public/{id}`

### 2.9 创作数据统计图表（🆕）

### 3.1 视觉小说「节点编辑」功能（❌ 未实现 —— 用户重点关心）

原文档 3.4 **分支逻辑编辑器**要求：

| 文档要求 | 实现状态 |
| --- | --- |
| 可视化流程图 | ⚠️ 只做了**只读展示**（ProjectView 剧情树弹窗），不能编辑 |

| 路径覆盖率检查 | ❌ 未实现 |
| 死循环检测 | ❌ 未实现 |

**关键缺口：**

1. **`branch_paths` 表已存在但完全没有 API**
   - 模型定义在 `back/app/models.py` L87-L95
   - 仅在 `services.py` 的**删除项目**（L292）和**删除角色**（L553）时被顺带清理

   - 只有 `python manage.py db upgrade` 类迁移才会建表，实际数据库中是否存在未知

2. **`script_contents.content_type` 有 `'选择'` 枚举值，但前端下拉只有「对话 / 旁白」**
   - `SceneEdit.vue` L109-L112 只有 `对话` 和 `描述`（旁白）两个选项，**「选择」类型无法创建**
   - 后端 `save_dialogue()` 支持 `选择`，但 `character_id`/`avatar_id` 会被强制置 `None`

3. **`script_contents.branch_condition`（JSON）字段无任何读写**
   - 模型有该字段，`save_dialogue()` 未写入，接口未返回

4. **前端 `ScriptContent` 接口有 `options: { text, target }[]` 字段**（`ProjectView.vue` L516），
   但没有 UI 创建选项，也没有后端支撑。

### 3.2 项目模板选择 `template_type`（❌ 前后端严重不一致）

- 原文档：`projects.template_type` ENUM('线性叙事','分支叙事','开放世界') NOT NULL
- 实际：
  - **`back/app/models.py` 的 `Project` 模型根本没有 `template_type` 字段**
  - 前端 `HomeView.vue`、`project.ts`、`individual.ts`、`ProjectView.vue` **都定义了 `template_type` 字段**，`HomeView` 表单里也把它放进 `projectForm`
  - `HomeView.vue` 「新建项目」对话框**没有模板选择控件**（只有标题 + 作品类型）
  - `HomeView` 里还有 `getTemplateTagType()` 函数，但**模板中未使用**
  - 后端 `create_project(user_id, title, genre, cover_url)` 收不到 `template_type`
  - `update_project()` 的文档字符串提到 `template_type`，但因为模型没这个属性，`setattr` 会被 `hasattr` 拦掉
- 结论：**这是一条从头到尾断掉的链路**，选题/模板功能实际不可用
