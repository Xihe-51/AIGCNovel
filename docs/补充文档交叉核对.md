## 一、最重要的发现：代码有三代版本，文档描述的是"最初设计"

把新老材料按时间排开，可以看到系统 AI 能力经历了**两次整体替换**：

| 版本 | 文本生成 | 图像生成 | 音频生成 | 证据 |
| --- | --- | --- | --- | --- |
| **第 1 代**（商业计划书描述，从未落地） | Ollama 本地部署 DeepSeek + LangChain + RAG + 向量库 | Stable Diffusion WebUI + Counterfeit-V2.5 + ControlNet 1.1 | Stable Diffusion 音频分支 + MusicGen-small | 3 份计划书 + `解决方案.docx` 的 3.3 节 |
| **第 2 代**（`代码信息.pdf` / `import os.docx` 中） | **硅基流动** `api.siliconflow.cn`（如 `Qwen/Qwen2.5-7B-Instruct`） | 本地 `diffusers` + `torch` 跑 Stable Diffusion（含 GPU/CPU 降级逻辑） | 本地 `transformers` 跑 MusicGen（`MusicgenForConditionalGeneration`） | 两份材料中的 `app/ai/services.py` 全文 |
| **第 3 代**（当前 `D:\AIGCNovel\back` 里的代码） | **DeepSeek 官方云 API** `api.deepseek.com`（`deepseek-chat`） | **通义万相** `wanx-v1` 异步 API（`dashscope.aliyuncs.com`） | **火山引擎 TTS 语音合成**（`openspeech.bytedance.com`） | `back/app/ai/services.py` L17-30 |

**结论**：商业计划书里的"Ollama / Stable Diffusion / MusicGen / ControlNet / LangChain / RAG / 向量数据库 / 有限状态机剧情链"等技术描述，**在任何一个代码版本中都没有实现过**，属于**申报材料层面的规划性描述**。
而第 2 代（硅基流动 + 本地 SD/MusicGen）在某个时间点被整体替换为第 3 代（全云 API），替换原因通常是本地推理需要 GPU、部署成本高。

> ⚠️ 这点很关键：如果论文 / 软著材料写的是 SD + ControlNet + MusicGen，而验收时跑的是云 API，两者对不上。

## 二、`代码信息.pdf` 与 `import os.docx` 揭示的"历史功能"（部分已消失）

对比文档版源码与当前代码的**接口清单**，可以看到系统在迭代中**加了一批、也丢了一批**。

### 2.1 文档版存在、当前代码里**新增**的接口（说明系统在持续扩展）

当前 `project` 蓝图比文档版多了 **14 个**接口，全部围绕「场景 / 对话 / 立绘」的细粒度 CRUD：

```
/scenes                    /scene/<scene_id>
/scenes/<project_id>       /scenes/upload
/scenes/<scene_id>         /dialogues
/dialogues/<scene_id>      /dialogues/<content_id>
/dialogues/reorder/<scene_id>   /dialogue_count/<project_id>
/create_character          /update_character
/avatars/<character_id>    /character/avatars/batch
/update_avatar             /delete_avatar/<avatar_id>
/upload_avatar
```

→ 说明「场景编辑 + 对话管理 + 立绘管理」是后期重点补强的模块，功能比设计文档时期丰富得多。

### 2.2 两版**共有**的接口（未变）

```
【AI】    /generate/text   /generate/image   /generate/music
【用户】  注册 / 登录 / profile / avatar / models(CRUD) / ai_model
         ai_history(含删除) / projects / statistics
         resources(CRUD) / resources/search / download / api/upload
【项目】  /project  /project/<id>  /project/<id>/cover  /project/public/<id>
         /projectAll  /projects  /characters/<project_id>
         /character/<id>  /character_avatar/<id>
```

> 注：文档版 `代码信息.pdf` 里 `/characters/<int:project_id>` **只注册一次**，而当前 `back/app/project/views.py` 中该路径在 L268 与 L359 **重复注册两次**（见《Bug清单》）。

### 2.3 文档版源码里的"已过滤"逻辑（与当前代码一致）

`代码信息.pdf` 中 `generate_and_save_text()` 的违禁词处理与当前代码**完全相同**：

```python
if forbidden_words:
    for word in forbidden_words:
        generated_text = generated_text.replace(word, "[已过滤]")
```

→ 说明 `forbidden_words=['']` 会污染整段文本的隐患是**历史遗留、一直存在**，不是最近引入的（对应《Bug清单》P1 项）。

## 六、附：材料解析技术备注（便于复现）
