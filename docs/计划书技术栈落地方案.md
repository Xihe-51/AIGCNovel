## 〇、先决条件：当前环境是「半坏状态」，必须先修

实测结果（`D:\AIGCNovel\back\.venv`）：

| 组件 | 状态 | 影响 |
| --- | --- | --- |
| `torch 2.11.0+**cpu**` | ❌ **CPU 版** | `cuda.is_available()=False`，**RTX 5060 完全用不上**，SD 会以 CPU 慢跑 |
| `pymysql` | ❌ **缺失** | **后端连不上 MySQL，当前根本起不来** |
| `redis 8.1.0` | ✅ 已装 | 计划书组件，白送的 |
| `celery 5.6.3` | ✅ 已装 | 计划书组件，白送的 |
| `diffusers 0.36.0` | ✅ 已装 | 本地 SD 可用 |
| `transformers` | ❌ 缺失 | MusicGen 跑不了 |
| `langchain` / `faiss` / `sentence_transformers` | ❌ 缺失 | RAG 人设库做不了 |
| Ollama `qwen2.5:7b` Q4_K_M | ✅ **服务已在跑** | 文本生成现成可用 |

### 本机硬件

| 项目 | 实测 |
| --- | --- |
| CPU | AMD Ryzen 9 8945HX（16 核 32 线程） |
| GPU | **NVIDIA RTX 5060 Laptop，8 GB 显存**，驱动 592.01 / CUDA 13.1 |
| 内存 | **16 GB**（偏紧） |
| 磁盘 | 见后文（模型需预留 ~15 GB） |

### ⚠️ 三个必须先决策的硬约束

1. **torch 必须重装为 CUDA 版**。但注意：RTX 5060 是 **Blackwell 架构（sm_120）**，需要 **CUDA 12.8+ 的 torch 2.7+ 才能支持**；且你的驱动是 CUDA 13.1，应装 `cu128` 或更新版本。
   - 若装不上：退化为 CPU 版跑 SD（512×512 约 3–8 分钟/张，基本不可用），或图像全部走云 API。
2. **8 GB 显存 + 16 GB 内存 = 只能单任务**。SD 与 Ollama 不能同时驻留，需用 Celery 串行队列 + 用完即卸（`pipe.to("cpu")` / `del`）释放显存。
3. **SD 1.5 系（Counterfeit-V2.5）在 Blackwell 上可能有兼容问题**，需实测；建议同时准备 SDXL-Turbo / SD-Turbo 等更省显存的替代。

### 📦 第 1 批：掴得住的（**本次范围**，不碰显存）

> 三个组件全部与 GPU 无关，纯 CPU/内存即可，风险最低、收益最高。

#### 1.1 Ollama 本地文本生成（替换 DeepSeek 云 API）

- **现状**：`ai/services.py:43 generate_and_save_text()` 调 `api.deepseek.com`
- **改造**：新增 `ai/backends/text_ollama.py`，用 `http://127.0.0.1:11434/api/chat`（Ollama 原生 HTTP，无需额外依赖）
- **配置**：`TEXT_BACKEND=ollama|deepseek`，默认 `ollama`
- **模型**：已装的 `qwen2.5:7b`（Q4_K_M，约 5 GB 内存占用）
- **要点**：
  - 沿用现有 `remove_think_tags()` 清洗
  - `forbidden_words` 为空字符串的 bug 顺便修掉（`if word:` 判空）
  - 保留云 API 作为 fallback
- **预计**：CPU 约 3–8 tok/s，生成 200 字约 30–60 秒（可接受）

#### 1.2 Redis 缓存层

- **接入点**：
  - AI 生成历史列表（`/user/ai_history`）缓存 60s
  - 项目统计（`/user/statistics`、`/user/projects`）缓存 30s
  - 用户会话 / JWT 黑名单
- **改造**：新增 `app/extensions.py` 统一管理 `redis_client`；`create_app()` 里初始化
- **降级**：Redis 不可用时自动退化为「无缓存直查」，不阻塞主流程
- **配置**：`REDIS_URL=redis://127.0.0.1:6379/0`

#### 1.3 Celery 异步任务

- **背景**：现在 `/generate/image` 是**同步阻塞**的（通义万相要轮询最多 120s），前端会卡死；本地 SD 更慢（分钟级），同步模式**根本不可用**
- **改造**：
  - 新增 `back/celery_app.py`（broker=Redis，backend=Redis）
  - 新增 `app/ai/tasks.py`：`task_generate_text` / `task_generate_image` / `task_generate_music`
  - `/ai/generate/*` 改为**投递任务、立即返回 `task_id`**
  - 新增 `GET /ai/task/<task_id>` 返回 `{state, progress, result}`
  - 前端 `AiView.vue` 改为轮询（每 2s），显示进度条
- **并发**：worker 并发设为 **1**（`--concurrency=1`），避免 8GB 显存被打爆
- **启动**：`celery -A celery_app worker -l info -P solo`（Windows 必须 `-P solo`）

**第 1 批验收**：
1. `/ai/generate/text` 用 Ollama 生成成功，日志显示未走外网
2. 重复请求 `/user/statistics`，第二次命中 Redis（打印 cache hit）
3. `/ai/generate/image` 立即返回 `task_id`，轮询可见 `PENDING → SUCCESS`

### 📦 第 2 批：剧情工程化（计划书技术核心）

#### 2.1 LangChain 上下文管理

- **现有替代**：`SceneEdit.vue` 已自制 `generateHistorySummary()` 做上下文压缩（近邻 5 条 + 远期摘要）
- **计划书要求**：LangChain Memory 模块
- **改造**：后端新增 `/ai/continue_story`，用 LangChain `ConversationSummaryBufferMemory` 管理多轮；前端不再自拼 prompt
- **依赖**：`langchain`、`langchain-community`、`langchain-ollama`

#### 2.2 RAG 角色人设库（向量检索）

- **目标**：保证人设一致性（计划书 3.3.2）
- **方案**：
  - 嵌入模型：`bge-small-zh-v1.5`（约 100 MB，CPU 可跑）或 Ollama 的 `nomic-embed-text`
  - 向量库：**FAISS**（本地文件，无需服务）或 ChromaDB
  - 数据源：`characters` 表（人名、性格、背景、`settings` JSON）
  - 流程：生成前按场景关键词检索 top-k 人设片段 → 注入 prompt
- **依赖**：`sentence-transformers`、`faiss-cpu`（或 `chromadb`）

#### 2.3 FSM 剧情链校验

- **现状**：前端 `SceneEdit.vue` 有一份 **FSM 四态机死代码**（模板零引用）；后端无
- **改造**：
  - 后端新增 `branch_paths` 的 **CRUD 接口**（填补最大功能缺口）
  - 实现剧情图校验：**路径覆盖率、死循环检测、孤儿节点检测**
  - 前端剧情树改为读 `branch_paths` **真实拓扑**（而非按标题关键词猜）
  - 打通 `SceneEdit`：开放「选择」类型对话 + 选项列表

### 📦 第 3 批：本地 SD 图像生成（双轨）

#### 3.1 本地 SD 后端

- **模型**：Counterfeit-V2.5（计划书指定，SD1.5 系，需先测 Blackwell 兼容性）
- **备选**：SDXL-Turbo / SD-Turbo（更省显存、更快，4 步出图）
- **改造**：新增 `ai/backends/image_local.py`，复活 `代码信息.pdf` 里那份 `initialize_pipe()` 逻辑（含 GPU/CPU 自动降级）
- **显存优化（8 GB 必做）**：
  - `enable_model_cpu_offload()`
  - `enable_attention_slicing()` + `enable_vae_slicing()`
  - 出图后 `del pipe; torch.cuda.empty_cache()`
  - 分辨率上限 512×768
- **ControlNet**：装 `controlnet_aux` + Counterfeit 配套 ControlNet 权重（约 1.5 GB/个）
- **配置**：`IMAGE_BACKEND=local|cloud|auto`

#### 3.2 双轨调度

- `auto` 模式下：本地队列空闲且显存够 → 本地；否则 → 云 API
- 前端模型下拉增加「本地 / 云端」标识

#### 3.3 音乐 / 语音

- **计划书**：MusicGen-small 生成**音乐**
- **现状**：已改成火山 TTS **语音**（语义都变了）
- **改造**：补 `transformers`，恢复 MusicGen-small（约 2 GB）；与 TTS 并存，前端区分「生成音乐 / 配音」两个入口

## 五、风险与对策

| 风险 | 概率 | 对策 |
| --- | --- | --- |
| Blackwell(sm_120) 上 torch cu128 装不上 | 中 | 降级用 SDXL-Turbo + cu126；仍不行则图像全走云 API |
| Counterfeit-V2.5（SD1.5）在 Blackwell 报错 | 中 | 换 SD-Turbo / SDXL-Turbo（同为二次元风格可调） |
| 8 GB 显存 OOM | 高 | 串行队列 + CPU offload + 切片 + 出图即卸；限 512×768 |
| 16 GB 内存放不下 Ollama + SD | 高 | 二者**不同时驻留**；用 Celery 串行隔离 |
| Redis Windows 安装麻烦 | 低 | 用 Memurai 或用 Docker；代码已做降级 |
| 首次下载模型慢（SD ~4 GB + ControlNet ~1.5 GB + MusicGen ~2 GB） | 高 | 预留 ~15 GB 磁盘，用 modelscope 镜像下载 |
