## 一、P0-1 异步链路（Redis + Celery）

### 环境

| 组件 | 状态 |
|---|---|
| Redis | 6380 端口可用（Docker 历史阻塞已由外部 Redis 绕过） |
| Celery worker | `python -m celery -A celery_app worker -l info -P solo --concurrency=1`（Windows 必须 `-P solo`） |
| 后端 | `back/manage.py`，8088，`use_reloader=False` |

`GET /ai/health` 实测：

```json
{"status": "ok",
 "cache": {"connected": true, "enabled": true},
 "async": {"enabled": true},
 "tts": {"ok": false, "reasons": ["VOLCENGINE_APPID 未配置", "VOLCENGINE_TTS_TOKEN 未配置"]}}
```

### 复测结论

- **文本接口走真实异步**：`/ai/generate/text` 返回 `202 + task_id`，
  再轮询 `GET /ai/task/<task_id>` → `{ready:true, result:{generated_text}}`。
- **两个「跳过项」转实测**：`test_batch12_e2e.py` 从「45 通过 / 0 失败 / 2 跳过（Redis 未连接）」
  变为 **49 通过 / 0 失败 / 0 跳过**。
- **`test_audit_e2e.py` 的 P1-6 改为异步感知**：原断言 `st == 200`，
  在 Redis 连通后必然失败（接口已改返回 202）；现改为「202 则轮询任务直至 ready 再断言」，
  回到 **36 通过 / 0 失败**，且断言的是**真实链路跑出来的结果**，比原来更严。
- **缓存命中不重复落库**：同 prompt 二次请求命中缓存直接复用 `generation_id`。

> 启动顺序坑点：**只起 Redis 不起 worker**，任务会永远 PENDING（前端一直转圈）。
> 两个进程都要活着。

## 二、P0-2 类型检查 + CI

### 类型检查

`npx vue-tsc --noEmit -p tsconfig.app.json --composite false`：**75 个错误 → 0**。

修复思路是「先修根因再修表面」：

| 文件 | 问题 | 处理 |
|---|---|---|
| `api/character.ts` | `avatar_url` 必需、导出缺失 | 改可选并导出 `Character`；`updateCharacterAvatar` 参数补类型 |
| `api/dialogue.ts` / `api/project.ts` / `api/scenes.ts` | 接口类型与实际返回不符 | 按后端真实返回结构声明（如 `publicExportProject` 返回 `{success,message}`） |
| `utils/request.ts` | `jwtDecode` 泛型缺失 | `jwtDecode<{identity?: string}>` |
| `ScenesManage.vue` | 52 个错误（拖拽/表单 ref 全 `any`） | refs 全类型化，`File \| null`、`setTimeout \| null`、事件参数补类型 |
| `HomeView.vue` | 重复 `Project` 接口 + 图表 ref | 复用 `api/project` 的 `Project`，ref 加 `\| null`，echarts 回调补 `any` |
| `ProjectView.vue` | `outCount[cid]` 索引、`AvatarType` | `Number(cid)`、`as AvatarType`、`is_default` 给 `boolean` |
| `IndividualView.vue` | 表单对象类型 | `password?: string` |

顺带修掉一个**运行时 Bug**：`ProjectView` 调 `updateCharacterAvatar` 传裸数字，
而后端 `/project/update_avatar` 读的是 `data['avatar_id']`，改为传 `{avatar_id}`。

`npm run build`（`run-p type-check build-only`）**通过**，exit 0（仅 Sass `lighten()` 弃用警告，非错误）。

### CI

新增 `.github/workflows/ci.yml`：

- **frontend job**：`npm ci` → `npm run build`（含类型检查）。
- **backend job**：装最小依赖 → `python -m compileall -q back/app ...` 语法门禁 →
  跑离线契约脚本 `docs/_src/test_music_voice_paths.py`（不加载模型、不联网）。

> 说明：完整 `back/requirements.txt` 含 `torch/diffusers/faiss` 等重型依赖，且有若干
> `file:///C:/...` 本机路径条目，CI 里装不动，所以后端 job 只装导入契约脚本所需轻量包。
> 需要 MySQL/Redis/Ollama/2GB 权重的端到端脚本（`test_audit_e2e.py`、`test_batch12_e2e.py`、
> `test_async_chain.py`、`test_local_sd_e2e.py`）在本地环境执行。
